# ADR-001: Асинхронная обработка KYC-проверки

## Контекст
KYC-провайдер может отвечать с задержкой, недоступность сервиса не должна
блокировать приём заявки клиентом.

## Решение
Обработка KYC вынесена в асинхронный поток через Kafka (Event Bus).
API возвращает 202 Accepted сразу после валидации, финальный статус клиент
узнаёт через уведомление или поллинг GET /application/{id}/status.

## Почему
- Клиент не должен ждать ответа KYC-провайдера синхронно (сценарий 5a)
- Система должна оставаться доступной даже при деградации KYC-сервиса

## Альтернативы
- Синхронный вызов KYC с таймаутом — отклонено: блокирует клиента, не решает проблему недоступности провайдера
