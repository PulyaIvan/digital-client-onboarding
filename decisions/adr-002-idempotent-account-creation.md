# ADR-002: Идемпотентное создание счёта в Core Banking

## Контекст
При сбое после успешного KYC, но до подтверждения создания счёта (сценарий 9a),
клиент не должен получить преждевременное уведомление об успехе, а счёт не должен
создаться дважды при повторной обработке события.

## Решение
Создание счёта в Core Banking выполняется идемпотентно (по application_id как ключу идемпотентности).
Уведомление клиенту отправляется только после подтверждённого создания счёта.

## Почему
Гарантирует ровно одно создание счёта на заявку, даже при повторной доставке события Kafka.
