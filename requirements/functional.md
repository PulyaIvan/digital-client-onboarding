# Функциональные требования


| FR-001 | Система должна предоставить клиенту форму для ввода персональных данных при регистрации 
| FR-002 | Система должна валидировать обязательные поля формы при попытке отправки заявки, подсвечивать незаполненные поля и блокировать отправку до их заполнения — на уровне API реализовано через `ErrorResponse.fieldErrors` (массив `{field, message}`), см. `api/openapi.yaml`
| FR-003 | Система должна отправлять данные заявки в KYC-сервис после успешной валидации формы 
| FR-004 | Система должна создавать банковский счёт в Core Banking при получении статуса "APPROVED" 
| FR-005 | Система должна отклонять заявку при получении статуса "REJECTED" 
| FR-006 | Система должна уведомлять клиента при переходе заявки в финальный статус ("APPROVED" или "REJECTED") |
| FR-007 | Система должна предоставлять клиенту возможность загрузить документы (паспорт, фото) как часть формы заявки 
| FR-008 | Система должна давать клиенту возможность восстановить доступ к заявке при утере токена доступа, подтвердив владение указанным при подаче email через одноразовый код — см. [ADR-006](../decisions/adr-006-access-recovery-otp.md) 
| FR-009 | Система должна предоставлять менеджеру список заявок с фильтром по статусу (очередь на ручную проверку) и полную историю переходов статуса по заявке (кто и когда принял решение) — `GET /application` и `history` в `ApplicationDetailsResponse`, `api/openapi.yaml`
